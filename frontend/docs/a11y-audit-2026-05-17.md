# Klondike Pro — WCAG 2.1 AA Accessibility Audit
**Date:** 2026-05-17  
**Scope:** All screens (Game, Daily, Profile, Friends, Leaderboard, Home, Login, Settings, Replay) + shared components  
**Method:** Static code analysis across all TSX/CSS files + colour contrast calculations  
**Standard:** WCAG 2.1 Level AA  

---

## Summary

| Severity | Count |
|---|---|
| Critical | 10 |
| Serious | 13 |
| Moderate | 16 |
| Minor / Best Practice | 10 |
| **Total** | **49** |

**Key themes:**
1. Game board is entirely mouse-only — no keyboard access to any card interaction
2. All 7 modal/sheet overlays lack ARIA dialog semantics and focus management
3. Every tab bar in the app is missing `role="tab"` / `aria-selected`
4. Multiple form inputs have no associated `<label>`
5. Accent-coloured buttons in Dark and Classic themes fail contrast (≈1.4–1.5:1)
6. No `:focus-visible` styles exist in Nav or Board CSS

---

## CRITICAL — breaks screen reader or keyboard use entirely

**[WCAG 2.1.1] Board/Board.tsx — All interactive card zones lack keyboard support**  
Stock pile, waste area, foundation piles, and tableau columns are all `<div>` elements with only `onClick`/`onPointerDown` handlers. No `role="button"`, no `tabIndex`, no `onKeyDown`. A keyboard-only user cannot interact with the board at all.  
*Fix:* Convert zones to `<button>` or add `role="button" tabIndex={0}` + `onKeyDown` for Enter/Space. Implement two-step keyboard move (select source → Tab to destination → confirm).

**[WCAG 2.1.1] Board/Board.tsx — Pause overlay has no keyboard dismiss**  
The "click backdrop to resume" overlay has no keyboard equivalent and does not auto-focus the Resume button.  
*Fix:* `useEffect` to focus Resume button when `timer.isPaused` becomes true; add Escape key handler.

**[WCAG 2.1.1] Settings.tsx — Theme cards and card-face design tiles are non-interactive `<div>`s**  
`div.theme-card` and `div.design-card` have `onClick` but no `role`, `tabIndex`, or `onKeyDown`. Completely unreachable by keyboard.  
*Fix:* Change to `<button>` or `role="radio"` within a `role="radiogroup"` with `aria-checked` for selected state.

**[WCAG 2.1.1] DailyCalendar/DailyCalendar.tsx — Calendar day cells are non-interactive `<div>`s**  
All day cells use `onClick` only. No `role`, `tabIndex`, keyboard handler.  
*Fix:* Change to `<button disabled={isFuture || !hasEntry}>`.

**[WCAG 2.1.1] Calendar/Calendar.tsx — Same issue as DailyCalendar**  
Day cells are `<div onClick>`. No keyboard access.  
*Fix:* Same — convert to `<button>`.

**[WCAG 4.1.2 / 4.1.3] WinModal.tsx & DailyWinModal.tsx — No dialog semantics**  
Both modals have no `role="dialog"`, `aria-modal`, `aria-labelledby`, focus trap, or focus auto-move.  
*Fix:* Add `role="dialog" aria-modal="true" aria-labelledby="win-title-id"` to inner modal `<div>`. `useEffect` to focus first element on open, restore focus on close.

**[WCAG 4.1.2 / 4.1.3] Profile.tsx — Delete account modal missing dialog semantics**  
`div.modal-overlay` / `div.modal-box` have no `role="dialog"`, no `aria-modal`, no focus trap.  
*Fix:* Add dialog role, auto-focus password input on open, trap Tab/Shift-Tab, Escape to close.

**[WCAG 4.1.2 / 4.1.3] Friends.tsx — Delete challenge modal missing dialog semantics**  
`div.sc-delete-backdrop` / `div.sc-delete-modal` have no ARIA dialog role, no focus trap.  
*Fix:* Same pattern as above.

**[WCAG 4.1.2 / 4.1.3] Game.tsx — `GameLeaderboard` drawer missing dialog semantics**  
`div.game-lb-backdrop` / `div.game-lb-drawer` function as a modal sheet but have no `role="dialog"`, `aria-modal`, or focus management.  
*Fix:* Add dialog semantics and focus trap.

**[WCAG 4.1.2 / 4.1.3] DayDetail/DayDetail.tsx — Bottom sheet missing dialog role**  
`div.day-detail-backdrop` is a modal overlay with no `role="dialog"`, `aria-modal`, focus management, or Escape key handler.  
*Fix:* Add `role="dialog" aria-modal="true"`, auto-focus close button on open, Escape to close.

**[WCAG 4.1.2 / 4.1.3] ResumeModal/ResumeModal.tsx — Modal overlay missing dialog semantics**  
`div.resume-overlay` / `div.resume-modal` have no `role="dialog"`, `aria-modal`, or focus management.  
*Fix:* Add dialog role and auto-focus Resume button on mount.

## SERIOUS — significantly impairs use

**[WCAG 4.1.3] Board/Board.tsx — Score and timer have no `aria-live` region**  
"Moves: N" and the timer have no `aria-live`. Score changes are silent to AT users.  
*Fix:* Wrap score/timer in `<div aria-live="polite" aria-atomic="true">`. Emit only on key events, not every tick.

**[WCAG 4.1.3] Board/Board.tsx — Win state not announced**  
When `game.isWon` becomes true, nothing announces the victory to AT.  
*Fix:* Inject a visually-hidden `role="status"` announcement: "You win! N moves in T time."

**[WCAG 2.4.7] Nav.css / Board.css — No `:focus-visible` styles anywhere**  
Neither file defines any `:focus` or `:focus-visible` rules. Browser default outline may be suppressed by `-webkit-tap-highlight-color: transparent` on `.nav-tab`.  
*Fix:* Add explicit `outline: 2px solid var(--color-accent); outline-offset: 2px` `:focus-visible` rules to all interactive elements.

**[WCAG 1.3.1 / 3.3.2] Profile.tsx — Display name input has no `<label>`**  
Input inside "Display Name" section has no `<label>` or `aria-label`.  
*Fix:* Add `<label htmlFor="displayName">Display Name</label>` or `aria-label="Display name"`.

**[WCAG 1.3.1 / 3.3.2] Profile.tsx — Change password inputs use placeholder as only label**  
All three password inputs have no `<label>`. Placeholder disappears on focus and is unreliable with AT.  
*Fix:* Add visible `<label>` elements or `aria-label` to each input.

**[WCAG 1.3.1 / 3.3.2] Profile.tsx — Delete account modal password input has no label**  
Password confirmation input has no `<label>` or `aria-label`.  
*Fix:* Add `aria-label="Password confirmation"`.

**[WCAG 1.3.1 / 3.3.2] Friends.tsx — League name input has no `<label>`**  
`<p class="league-form-label">` is not programmatically linked to the input.  
*Fix:* Change `<p>` to `<label htmlFor="league-name-input">` and add matching `id` to input.

**[WCAG 4.1.2] Multiple screens — Tab bars missing `role="tab"` / `aria-selected`**  
Affects: Daily.tsx (Game/Leaderboard/Calendar), Profile.tsx (Stats/Calendar/Display/User), Friends.tsx (Friends/Leagues/Challenges), Login.tsx (Sign In/Register). All use plain `<button>` with no ARIA tab pattern.  
*Fix:* Add `role="tablist"` to tab wrapper, `role="tab" aria-selected={isActive}` to each button, `role="tabpanel" aria-labelledby` to each panel.

**[WCAG 2.1.1 / 4.1.2] Friends.tsx — Swipe-reveal Delete/Hide buttons unreachable by keyboard**  
Delete/Hide actions inside `.sc-swipe-action` are only exposed via touch swipe. No keyboard alternative.  
*Fix:* Add a visible "⋯" overflow-menu button per challenge card providing keyboard access to Delete/Hide.

**[WCAG 1.4.3] Accent-background buttons — text contrast failure in Dark and Classic themes**  
Any button with `background: var(--color-accent)` and `color: var(--color-text-primary)` (or similar light text) will fail:
- Dark: `#e6edf3` on `#c9a84c` ≈ **1.5:1** (needs 4.5:1) — FAIL
- Classic: `#f0ead6` on `#f5c518` ≈ **1.4:1** — FAIL
Elements confirmed to use `color: #000` on accent already pass. Audit all `btn-primary` / `btn-danger` usages.  
*Fix (DEV-238):* Set `color: #000` explicitly on all accent-background elements in Dark/Classic themes. Use `color: #fff` on Modern's `#2563eb` (passes at 4.5:1).

## MODERATE — annoying but workaroundable

**[WCAG 1.4.11] Board — Empty pile zones may fail non-text contrast (3:1)**  
`border: 1.5px dashed var(--color-border)` — `--color-border` is `rgba(255,255,255,0.08)` on `#0d1117` — this is essentially invisible.  
*Fix:* Use a higher-contrast border (e.g. `rgba(255,255,255,0.25)`) for empty pile placeholders.

**[WCAG 1.3.1] Profile.tsx — Avatar `<div>` is clickable but lacks button role**  
`div.profile-avatar` triggers a file input via `onClick` but has no `role="button"`, `tabIndex`, or `onKeyDown`.  
*Fix:* Change to `<button type="button" aria-label="Change avatar">`.

**[WCAG 1.1.1] Card.tsx — CSS-rendered card faces have no accessible card name on container**  
For Standard/Classic/Minimal designs the `<div class="card-face">` contains rank/suit as separate `<span>` fragments, not a unified accessible name.  
*Fix:* Add `aria-label={\`${rankLabel(rank)} of ${suit.name}\`}` to each card face container.

**[WCAG 1.1.1] Board.tsx — Stock recycle zone renders only `↺` with no accessible label**  
The `<div class="stock-empty">↺</div>` has no `aria-label` describing the action.  
*Fix:* Add `aria-label="Recycle stock pile"` (once converted to `<button>`).

**[WCAG 1.1.1] DailyCalendar.tsx — HeartIcon SVGs convey Won/Played state with `aria-hidden="true"`**  
No text alternative for calendar cell status.  
*Fix:* Add visually-hidden text ("Won", "Played") alongside each icon.

**[WCAG 4.1.2] DailyCalendar.tsx & Calendar.tsx — Nav buttons use `title` instead of `aria-label`**  
`<button title="Previous month">‹</button>` — `title` is not reliably announced by all ATs.  
*Fix:* Replace `title` with `aria-label` on all calendar navigation buttons.

**[WCAG 4.1.3] Game.tsx — "Dealing…" spinner has no live region**  
`<div class="game-spinner">Dealing…</div>` has no `role="status"` or `aria-live`.  
*Fix:* Add `role="status"`.

**[WCAG 4.1.3] Daily.tsx — "Loading today's challenge…" has no live region**  
*Fix:* Add `role="status"`.

**[WCAG 4.1.3] AuthGuard.tsx — "Loading…" text has no live region**  
*Fix:* Add `role="status"` to the container `<div>`.

**[WCAG 2.4.2] All screens — No document `<title>` update per route; no `<main>` landmark**  
Most screens render content without a `<main>` wrapper. Document title stays "Klondike Pro" on all routes.  
*Fix:* Add `<main>` to each screen's top-level container. Use `document.title = 'Game – Klondike Pro'` in route-level `useEffect`.

**[WCAG 2.4.1] Nav.tsx — `<nav>` has no `aria-label`**  
*Fix:* Add `aria-label="Main navigation"`.

**[WCAG 1.3.1] Leaderboard.tsx / Home.tsx — `<header>` inside `<div>` is not a banner landmark**  
`<header>` only carries `role="banner"` when a direct child of `<body>`. Nested inside a screen `<div>`, it's just a `<div>`.  
*Fix:* Wrap screen content in `<main>` and keep `<header>` outside, or add `role="banner"` explicitly.

**[WCAG 4.1.2] Settings.tsx — Colour swatch buttons have hex codes as `aria-label`**  
`aria-label="#1c2333"` is meaningless to AT users.  
*Fix:* Add human-readable labels (e.g. "Dark Navy") alongside hex values.

**[WCAG 4.1.2] Settings.tsx — Animations toggle: `<input>` accessible name is empty**  
The displayed label text is outside the `<label>` element.  
*Fix:* Move label text inside `<label>` or add `aria-label="Animations enabled"` to the input.

**[WCAG 2.4.3] WinModal / GameLeaderboard / DayDetail — Focus not restored on modal close**  
No mechanism to return focus to triggering element after close.  
*Fix:* Capture `document.activeElement` before modal open; restore on close.

**[WCAG 3.3.1] Profile.tsx — Password error, delete error, avatar error not announced**  
`{pwError && <p class="error-text">{pwError}</p>}` and similar error paragraphs have no `role="alert"`.  
*Fix:* Add `role="alert"` to error paragraphs.

**[WCAG 3.3.1] Friends.tsx — Invite status message has no live region**  
`<p class="invite-msg">{inviteMsg}</p>` appears/disappears silently.  
*Fix:* Add `aria-live="polite"` to the container.

## MINOR / BEST PRACTICE

**[WCAG 2.4.4] Friends.tsx — Challenge tab badge `♥` character read alongside `aria-label`**  
*Fix:* Add `aria-hidden="true"` to the `♥` character.

**[WCAG 1.4.1] Friends.tsx — "New" badge on challenge cards: verify contrast across themes**

**[WCAG 4.1.2] ReplayControls.tsx — Play and Next buttons both render `▶`**  
AT users can distinguish via `aria-label`; sighted users may be confused.  
*Fix:* Use `⏭` or `›` for Next.

**[WCAG 1.4.4] Nav.css — Nav label font-size is 10px**  
Below comfortable legibility threshold. Increase to 12px minimum.

**[WCAG 2.4.3] WinModal / DailyWinModal — Focus not restored to trigger after close**  
For win modals the trigger is the game state, not a button — annotate this as accepted.

**[WCAG 1.1.1] Home.tsx — Button emoji (`🃏`, `🌅`, `👥`) read verbatim by screen readers**  
*Fix:* `<span aria-hidden="true">🃏</span>` wrapper on all decorative emoji.

**[WCAG 1.1.1] Leaderboard.tsx — `🏆` in `<h1>` read verbatim**  
*Fix:* Same emoji wrapper pattern.

**[WCAG 3.3.1] Login.tsx — No `role="alert"` on error messages**  
`{error && <p class="login-error">{error}</p>}` — add `role="alert"`.

**[WCAG 2.1.2] Board — No keyboard escape from the active game once keyboard nav is added**  
Ensure Tab can reach the Nav and Escape is handled gracefully.

**[WCAG 1.4.3] Modern theme — white text on `#2563eb` accent is borderline 4.5:1**  
Confirm `btn-primary` in Modern theme uses `color: #fff` and that this passes. (White on `#2563eb` ≈ 4.5:1 — borderline pass.) Consider darkening accent slightly to `#1d4ed8`.

## Recommended fix priorities for DEV-237 and DEV-238

### DEV-237 (ARIA / keyboard)
1. Board keyboard navigation (biggest effort — needs game design decision on move model)
2. Dialog semantics + focus trap on all 7 modals (mechanical, high impact)
3. Tab bar ARIA on Daily, Profile, Friends, Login (mechanical)
4. Missing form labels: Profile (3), Friends (1)
5. `aria-live` on score, timer, win announcement, loading states, error messages
6. `role="status"` on all loading spinners
7. Convert avatar clickzone, Settings tiles, calendar cells to `<button>`
8. `:focus-visible` styles on all interactive elements

### DEV-238 (colour contrast)
1. `btn-primary` text colour on accent bg — Dark and Classic themes
2. Empty pile border contrast
3. Colour swatch `aria-label` readable names
4. Modern accent darkening (optional — borderline pass)
